# 数据字典 · Phyphox 加速度导出字段说明

## 1. 原始 CSV 的列结构

Phyphox「Acceleration without g」导出的 CSV，标准列名如下（不同版本/系统语言略有差异）：

| 列序 | 英文列名（常见） | 中文列名（部分系统） | 单位 | 含义 |
| --- | --- | --- | --- | --- |
| 1 | `Time (s)` | `时间 (s)` | 秒 | 从点击开始采集起的相对时间戳 |
| 2 | `Absolute acceleration (m/s^2)` | `绝对加速度 (m/s^2)` | m/s² | 三轴合成幅值 `sqrt(x²+y²+z²)`，**已扣除重力** |
| 3 | `X (m/s^2)` | `X (m/s^2)` | m/s² | 手机坐标系 X 轴（屏幕横向） |
| 4 | `Y (m/s^2)` | `Y (m/s^2)` | m/s² | 手机坐标系 Y 轴（屏幕纵向） |
| 5 | `Z (m/s^2)` | `Z (m/s^2)` | m/s² | 手机坐标系 Z 轴（垂直屏幕向外） |

> 本仓库分析脚本 `scripts/analyze_gait.py` 已内置上述列名的自动映射，并支持 `Sensor Logger`、`Physics Toolbox` 的常见变体（如 `seconds_elapsed`、`x`、`y`、`z`、`az`…）。若你的导出文件报"找不到时间列/X 列"，只需在脚本顶部的 `COLUMN_ALIASES` 字典里加一行别名即可。

## 2. 坐标系的关键提醒

手机在裤兜里的姿态**不是固定**的，所以：

- **X/Y/Z 的物理方向会随手机姿态旋转**，不能直接跨组对比"Z 轴是不是指向上下"。
- 因此本课题的稳健做法是：**主判据用「合加速度」**（旋转不变，只反映运动强度），辅以频域特征（也不受旋转影响）。
- 只有当你在采集时**严格保持手机姿态一致**（例如每次都屏幕朝内、竖直插入前口袋），X/Y/Z 的语义才可跨组比较。`sample_index.csv` 里的 `phone_placement` 字段就是用来记录这件事的——如果姿态不一致，报告里必须注明"仅用合加速度分析"。

## 3. 分析脚本产出的中间表 `feature_table.csv`

切窗策略：**2 秒不重叠滑窗**（200 Hz → 每窗 400 个采样点），去头 3 s、去尾 1.5 s。每行一个窗口。

> 窗长在脚本顶部 `WINDOW_S` 可调。**它不是一个自由参数**：2 s 窗给出 0.5 Hz 频率分辨率，是步频判据可用的前提；若录制时长不足 15 s，2 s 窗切不出足够样本，只能被迫缩短到 1 s，代价是分辨率掉到 1 Hz，频域判据随之失效。所以「先保证录制 30 秒」比「事后调窗长」重要得多。

| 字段 | 类别 | 定义 | 为什么要它 |
| --- | --- | --- | --- |
| `file` | 元信息 | 来源文件名 | 溯源 |
| `state` | 标签 | 从文件名解析出的状态代号 | 真值标签 |
| `rep` | 元信息 | 组号 01/02/03 | 重复性检验 |
| `win_idx` | 元信息 | 窗口在该文件内的序号 | 定位异常窗口 |
| `win_start_s` | 元信息 | 窗口起始时刻（秒） | 与原波形对齐 |
| `mean_mag` / `std_mag` / `rms_mag` | 时域 | 合加速度的均值/标准差/均方根 | **静止 vs 运动**最灵敏 |
| `p2p_mag` | 时域 | 峰峰值（max − min） | 冲击强度（跑步落地） |
| `sma` | 时域 | 信号幅度面积 `mean(|x|+|y|+|z|)` | 能量消耗的经典步态指标 |
| `zcr` | 时域 | 合加速度过零率 | 抖动频率的粗略代理 |
| `skew_mag` / `kurt_mag` | 高阶 | 偏度 / 峰度 | **上下楼梯**的对称性线索 |
| `corr_xy` / `corr_yz` | 相关 | 两轴相关系数 | 轴向耦合模式 |
| `dom_freq_hz` | 频域 | FFT 幅值谱峰值频率（0.5–15 Hz 内） | **步频 → 慢走 vs 快跑** |
| `spec_energy` | 频域 | 频谱总能量 | 运动总强度 |
| `spec_entropy` | 频域 | 归一化谱熵 | 运动的"规律性"，跑比走更集中 |
| `band_0_3` / `band_3_8` / `band_8_20` | 频域 | 三个频带的能量占比 | 分频段刻画动作 |

## 4. 阈值规则文件 `threshold_rules.json`

脚本用**单层决策树**（深度 ≤ 4）拟合特征 → 4 状态的映射，导出为可读的 if-else 规则：

```json
{
  "rule_id": "dt_depth4_cv3",
  "tree": { ... },
  "as_pseudocode": [
    "if std_mag <= 0.142: → S1_STATIC",
    "elif dom_freq_hz <= 2.05: → S2_WALK",
    "elif dom_freq_hz <= 2.35: → S4_STAIR",
    "else: → S3_RUN"
  ],
  "holdout_accuracy": 0.87,
  "per_state_recall": { "S1_STATIC": 1.00, "S2_WALK": 0.91, "S3_RUN": 0.94, "S4_STAIR": 0.68 }
}
```

> 这些数值全部由**你的真实数据**训练得出，脚本不会写死任何结果。首次运行前 `threshold_rules.json` 不存在是正常的。

## 5. 采集元信息表 `sample_index.csv` 字段

| 字段 | 填写说明 |
| --- | --- |
| `file` | 采集完成后重命名好的文件名 |
| `state` | `S1_STATIC` / `S2_WALK` / `S3_RUN` / `S4_STAIR` |
| `rep` | 组号 1/2/3 |
| `start_time` | 该段开始时刻，`YYYY-MM-DD HH:MM` |
| `duration_s` | 实际有效动作时长（从"站定 3 秒"之后算起） |
| `phone_model` | 例：`Redmi Note 12 / Android 14` |
| `phone_placement` | 例：`右前裤兜，屏幕朝内，竖直` |
| `site` | 例：`信通学院 4 楼走廊直线段 30m` |
| `sampling_hz` | Phyphox 设置里显示的采样率 |
| `completed` | `Y` / `N` |
| `note` | 异常说明（如"仅上楼"、"中途被同学叫停"） |
