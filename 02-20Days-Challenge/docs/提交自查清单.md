# 提交自查清单

打分项：① 7天日志 25 分　② 3次迭代 diff 20 分　③ 源码+8人反馈 15 分。
逐条打勾再提交，任何一条不满足都会丢整块分。

---

## ① 连续 ≥7 天自动化运行日志（25 分）

- [ ] `process_logs/` 下有 ≥7 个 `YYYY-MM-DD.jsonl`，日期连续无缺
- [ ] **若不足 7 天**：README 必须有《关于日志天数的说明》，写清起止日期、实际天数、
      补偿措施（如每日 3 次运行）与追加提交时间。含糊带过比明说更伤分，见 `docs/应对截止时间.md`
- [ ] `git log --format="%ad %s" --date=short -- process_logs/` 显示**逐日**提交，不是一次性推 7 个
- [ ] 每条日志含 `ts`（秒级 ISO8601）、`dur_ms`、`event`、`run_id`
- [ ] `run_end` 里有 `calls` 与 `counters`（调用频次可统计）
- [ ] 有 `error` 事件，且 `error_type` + `stage` 可解释（**没有报错的日志反而不可信**）
- [ ] 脱敏到位：搜不到手机号、学号、真实姓名、`C:\Users\你的名字`
  ```bash
  grep -rE "1[3-9][0-9]{9}|C:\\\\Users" process_logs/ && echo "发现未脱敏内容！"
  ```
- [ ] `process_logs/README.md` 说明了字段含义与脱敏策略
- [ ] 某天无通知时，仍有 `run_start`/`inbox_scan`/`run_end`（空跑也是记录）
- [ ] 有 `tools/register_task.ps1` 证明是定时任务而非手动点

## ② 至少 3 次基于日志的 Git 迭代（20 分）

- [ ] 有 ≥3 个版本 tag：`git tag` 能看到 `v0.1.0 v0.2.0 v0.3.0 v0.4.0`
- [ ] 每个版本的 commit message 里**引用了具体日志证据**（日期 / `run_id` / 指标数字）
- [ ] `iterations/` 下有对应的 `.diff` 文件，且 diff 只涉及相关文件（不夹带无关改动）
- [ ] `iterations/` 下有改动**前**的 `log_digest_*.md`（证明是日志驱动的）
- [ ] 每次迭代后日志指标有可观测变化（`errors` 下降 / 漏抽率下降 / 新增事件）
- [ ] 改动能被"一句话说清"——如果一个 commit 改了 8 个文件 5 个功能，评审会觉得是凑数

## ③ 完整源码 + 8 位真实用户反馈（15 分）

- [ ] 源码可跑：新机器上 `python run.py run` 能出日报（无隐藏依赖）
- [ ] `tests/fixtures/` + `python run.py selftest` 有可复现的自测
- [ ] README 写清了：痛点、方案、架构、怎么运行、日志规范、迭代史
- [ ] `docs/用户反馈表.md` 填满 8 行，每行有使用天数、卡点、意愿分、原话
- [ ] `docs/feedback/u01..u08.png` 有截图证据（打码）
- [ ] `process_logs/` 里能看到 8 位用户的 `web_extract` 调用，且与反馈表的使用天数对得上
  ```bash
  grep -c '"event": "web_extract"' 02-20Days-Challenge/process_logs/*.jsonl
  ```
- [ ] 反馈与迭代有对应关系（哪条反馈导致了哪次改动）
- [ ] 隐私：反馈表用 U01–U08 编号，不出现真实姓名

## 面试可能被追问的 6 个问题（提前准备）

| 追问 | 考察点 | 怎么答 |
| --- | --- | --- |
| 为什么用规则而不用大模型？ | 权衡判断 | 每天十几条通知、要离线可用、要可解释；大模型有用量成本和网络抖动，规则错了能一眼看出改哪行。若哪天规则覆盖不住，再上"规则为主 + LLM 兜底"。 |
| 某天 `error` 为什么这么多？ | 真实性溯源 | 打开那天 JSONL，指出是截图通路缺依赖（`EngineMissing`），并说明 v0.2.0 怎么修的。 |
| 你怎么保证 8 个人真用了？ | 真实性 | 出示反馈截图、使用天数与日志 `calls` 的交叉印证。 |
| 如果预算减半 / 断网？ | 应变 | 本来就是零依赖纯标准库 + 本地 SQLite，断网完全不影响；预算减半意味着不能买 OCR 云服务，正好回到本地 tesseract。 |
| 这个工具最大的局限是什么？ | 诚实度 | 群消息还得手动复制粘贴，没法自动抓。想做自动抓取需要微信机器人，合规风险大，我选择不做。 |
| 用户隐私怎么处理？ | 工程伦理 | 正文不入库、只存 sha 前 12 位；日志正则脱敏；真实通知原文 `.gitignore` 掉；反馈匿名编号。 |
