# csv_series/ —— 这 75 份 CSV 是「音频的降采样视图」，不是加速度数据

> 写这一页，是因为这个目录最容易被误读。文件名和 WAV 一一对应，放在"时序 CSV"的位置上，很容易被当成第二路传感器（振动）的数据。**它不是。**

## 一、它到底是什么

由 `run.py export_csv` 从 `raw_audio/*.wav` 直接生成（源码见 [`../run.py`](../run.py) `cmd_export_csv`）：

```python
x, sr = dataset.load_steady(s)      # 读 WAV，去头去尾各 0.5 s → 2.0 s
step = max(1, sr // rate)           # 16000 // 1000 = 16
y = x[::step]                       # 每 16 点取 1 点
```

| 项 | 值 |
| --- | --- |
| 列 | `t_s, amplitude` |
| 采样率 | 1000 Hz（由 16 kHz 每 16 点抽取 1 点） |
| 长度 | 2000 行 = 2.0 s（与 WAV 的 3.0 s 不同，这里已去掉头尾） |
| 幅值范围 | 归一化到 ±1（实测 −0.977 ~ +0.976），**有负值** |
| 物理量 | **归一化声压波形**，不是 m/s² |

判断依据很简单：**加速度是 m/s²，量级是 0~10；这批数值全在 ±1 之间且有正负交替，是归一化的音频波形。**

## 二、为什么要导出它

1. 让人**不装任何工具**也能打开看：Excel / 记事本直接读，能手算 RMS 与峰峰值；
2. 它是「特征提取器与声道无关」的现成物证——`features.extract()` 只要求"一维等间隔序列 + 采样率"，喂 CSV 或喂 WAV 得到同一套 34 维特征，演示见 [`../scripts/demo_csv_channel.py`](../scripts/demo_csv_channel.py)。

## 三、它不能用来做什么

| 不能 | 原因 |
| --- | --- |
| 做 2–8 kHz 的频谱判据 | 1 kHz 抽取后奈奎斯特上限只有 **500 Hz**，擦碰指纹（4–8 kHz）在这里根本不存在 |
| 当成加速度计数据 | 它是声压波形，量纲与物理来源都不同 |
| 替代 WAV 做任何结论 | 有损视图。`run.py` 全流程的一切分析都读 `raw_audio/*.wav`，CSV 只用于人工翻阅 |

## 四、和考核要求的关系（如实说明）

大纲项目三必交项写的是「5 种工况 × 15 组原始 **WAV/CSV** 序列」。
本仓库 WAV 齐（75 段，是真数据源），CSV 也齐（75 份），但**这一项里的"加速度"通道是缺的**：

- 题目要求「手机麦克风**与**加速度计」两路；
- 本轮只采了麦克风。这一点在 [`../REPORT.md`](../REPORT.md) §8 局限第 6 条、[`../docs/提交自查清单.md`](../docs/提交自查清单.md) 都已写明，`check_delivery.py` 也把「加速度计数据通道」标成 WARN 而不是 OK。

所以请不要把本目录理解成"两路都做了"。它是**一路数据、两种可读格式**。
