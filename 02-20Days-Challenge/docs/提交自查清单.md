### 关于 CSV 的口径说明

`csv_series/` 里的 75 份 CSV 是**由 WAV 降采样导出的时序**（`run.py export-csv`，默认 1 kHz），不是独立的传感器通道。

- 它的用途：让人能用 Excel 打开、手算 RMS 与峰峰值、肉眼核对波形；
- 它的限制：1 kHz 的奈奎斯特上限只有 500 Hz，**不能用来做高频频谱分析**。所有分析一律读 `raw_audio/*.wav`。

我把它写清楚，是因为"75 份 CSV"和"75 份独立通道的 CSV"在评审眼里可能是两回事，我不想让它被误读。

### 关于实验照的短板

8 张照片都是设备照（正面丝印、侧面、背面、铭牌、旋钮、手机置于扇座），**但没有一张是"胶带配重""纸板遮挡"这些异常工况的现场照**。这是本次的缺口：照片拍于设备检查阶段，做异常工况时没有补拍。

补齐方法很明确：每个异常工况补 1 张特写（胶带位置、纸板覆盖面积、网罩接触点），成本 5 分钟。本轮没做。

### 关于加速度计通道

**没做，就是没做。** 不写"等比例可用于加速度"这种话糊过去。

代码那边已经具备接进去的条件：`features.extract(x, sr)` 只要求"一维等间隔序列 + 采样率"，`scripts/demo_csv_channel.py` 用一份 CSV 时序跑通了同一套 34 维特征，证明它不依赖 WAV 格式。但**能接 ≠ 已经接了**。

补采路径已落成可执行的方案：[`加速度通道补采方案.md`](加速度通道补采方案.md)。要点是先做奈奎斯特核对——200 Hz 采样下高档 BPF 181 Hz 不可观测、4–8 kHz 擦碰指纹物理不可见，所以振动通道只能做 1×/2× 阶次与冲击判据，**不能替代声学**。配套 `scripts/import_accel.py` + `scripts/accel_check.py`，合成数据自检通过。

### 自查发现的问题

34 维里**有 7 维分离度 < 5**（`band_100_300`、`crest_factor`、`impulse_factor`、`clearance_factor`、`band_20_100`、`h2_ratio`、`h3_ratio`）。其中 `h2_ratio`/`h3_ratio` 基本无信息。

我选择**保留并标注**，而不是删掉凑一个漂亮的"34 维"——因为删掉会让"为什么是 31 维/28 维"变成一个新的问题。完整排名在 `features/feature_summary.csv`，读者可以自己看哪些是死重。

### 关于 100% 这个数字

必须说清楚口径：**25 个样本全对，只能把准确率的下界推到 86.7%**，不能证明"准确率是 100%"。要收窄区间得靠扩大留出集，就需要再有几百段独立录音。

而且**这个 100% 本身说明数据太容易**：6 个正则强度全部 100%、3 层决策树 4 个阈值就分完 5 类、每类 3 段就稳定。所以我把报告的重心放在"怎么把它弄难"（§6 抗噪 + §7 压力测试）上，而不是再刷一遍准确率。

### 关于盲测视频

大纲中文版这一条写的是"盲测准确率与抗噪报告"（无视频），英文版写的是 "blind test video"。我按中文版执行，**没有录视频**。

如果评审按英文版要求，补齐方式是一条命令：

```bash
python run.py blind seal && python run.py blind predict && python run.py blind score
```

屏幕录制这条流程即可，重点是要能看到 `predict` 阶段**只读 `blind_clips/`**、`score` 阶段才打开答案键。整个过程不需要任何剪辑。
