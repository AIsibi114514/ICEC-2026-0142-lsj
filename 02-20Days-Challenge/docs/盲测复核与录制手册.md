## 三、三条命令，按顺序跑

### ① 预测：只用封存片段，全程不碰标签

```bash
.venv\Scripts\python.exe run.py blind predict
```

实际输出（2026-11-25 复跑）：

```
[blind:predict] 25 段完成预测（全程未接触标签）  (210 ms)
[blind:predict] 预测分布：{'C4_obstruction': 5, 'C3_imbalance': 5, 'C5_rubbing': 5, 'C1_normal_low': 5, 'C2_normal_high': 5}
```

**这里要念出来的点**：输入只有 `results/blind_clips/` 下的 25 个 `B01.wav ~ B25.wav`——文件名被改成 B 编号，听不出、看不懂是哪一类。模型是 `models/model_blind.json`，训练时那 25 段被 `split_train_test` 排除了。

### ② 打分：这时才打开答案键

```bash
.venv\Scripts\python.exe run.py blind score
```

```
[blind:score] 25/25 = 100.0%（95%CI 86.7%~100.0%）  macro-F1 1.000  (12 ms)
true\pred          C1_normal_low  C2_normal_high    C3_imbalance  C4_obstruction      C5_rubbing
C1_normal_low                  5               0               0               0               0
...
```

**这里要念出来的点**：混淆矩阵是对角阵，没有一次跨类错误；但 25 个样本的 95% 置信区间下界只有 86.7%，**100% 不等于"绝不会错"**。

### ③ 校验：证明答案键没被事后改过

```bash
.venv\Scripts\python.exe run.py blind verify
```

```
[blind:verify] 答案键一致 OK  recorded=cb5ba40b21dcf6dc… actual=cb5ba40b21dcf6dc…
```

**这里要念出来的点**：`results/blind_manifest.json` 在 11-24 封存那一刻就把 `blind_key.csv` 的 sha256 记下来了（`cb5ba40b…`）。今天重算一遍还是这个值，说明答案键从封存到现在**一个字节都没动**。这一步才是盲测可信的支点——否则"先看答案再调模型"谁都能做到。

## 四、录屏怎么录

用 Windows 自带的 **Xbox Game Bar**，不用装任何东西：

1. `Win + G` 打开捕获面板 → 点"开始录制"（或直接 `Win + Alt + R` 开录/停录）
2. 录制对象：终端窗口 + 需要时切到 `blind_manifest.json` / `blind_score.json` 看一眼
3. 时长目标 **2–3 分钟**，不要超过 5 分钟（评审没耐心）
4. 建议开麦克风口播——**有真人声音比纯静默录屏可信得多**
5. 录完默认存在 `视频\Captures\`，文件名形如 `盲测复核_2026-11-25.mp4`

**分辨率**：终端字号先调到 16–18 pt 再录，不然 1080p 下字看不清。

### 建议的镜头顺序（3 分钟，含现场重封存）

> **为什么可以现场跑 `seal`**：封存的随机种子固定为 20261123，留出样本按"每类最后 5 条"切分，
> 因此重跑 `blind seal` 会逐字节复现同一份 `blind_key.csv`，sha256 仍是 `cb5ba40b21dcf6dc…`。
> 2026-11-25 22:06 在临时副本上实测确认过。**现场重封存 + 哈希不变**，是这套协议最有说服力的一幕。

| 时间 | 画面 | 命令 | 说什么 |
| --- | --- | --- | --- |
| 0:00–0:25 | 终端，`ls results/blind_clips` | — | "25 个片段，文件名 B01–B25，看不出类别；11-24 从 75 段里留出，训练时没见过" |
| 0:25–0:45 | 打开 `results/blind_manifest.json` | — | "封存时记下了答案键的 sha256 与随机种子 20261123" |
| 0:45–1:10 | 跑封存 | `python run.py blind seal` | "现在重新封存一次，看哈希会不会变——不变才说明它真的只取决于种子和数据" → 屏幕上打出 `sha256=cb5ba40b21dcf6dc…` |
| 1:10–1:40 | 跑预测 | `python run.py blind predict` | "这一步只读音频和模型，代码里没有任何读标签的路径" |
| 1:40–2:15 | 跑打分 | `python run.py blind score` | "25/25，混淆矩阵是对角阵；但 25 个样本的置信区间下界只有 86.7%" |
| 2:15–2:40 | 跑校验 | `python run.py blind verify` | "`recorded` 与 `actual` 相同，说明封存之后答案键没被改过一个字节" |
| 2:40–3:00 | 打开 `REPORT.md` §5.3 | — | "100% 是警报不是成绩：3 层决策树 4 个阈值就分完 5 类，说明这批数据太好分了" |

**最后 20 秒讲缺点，不要讲成绩。**

### 命令卡（录屏时照着敲，一条一条来）

```bash
# ① 现场重封存（约 2.6 s）—— 输出应含 sha256=cb5ba40b21dcf6dc…
python run.py blind seal

# ② 盲测预测（约 0.3 s）—— 只读 results/blind_clips/ 与 models/model_blind.json
python run.py blind predict

# ③ 启封打分（约 0.01 s）—— 此时才第一次读 blind_key.csv
python run.py blind score

# ④ 哈希校验（瞬时）
python run.py blind verify
```

四步的预期输出（照这个对，对不上就停下来查）：

| 步骤 | 关键输出行 |
| --- | --- |
| seal | `[blind:seal] 25 段匿名化 → results/blind_clips/`<br>`[blind:seal] 答案键 sha256=cb5ba40b21dcf6dcd7911ba33322af9c… 已封存` |
| predict | `[blind:predict] 25 段完成预测（全程未接触标签）`<br>`[blind:predict] 预测分布：{'C4_obstruction': 5, 'C3_imbalance': 5, ...}` |
| score | `[blind:score] 25/25 = 100.0%（95%CI 86.7%~100.0%）  macro-F1 1.000` + 5×5 混淆矩阵 |
| verify | `[blind:verify] 答案键一致 OK  recorded=cb5ba40b21dcf6dc… actual=cb5ba40b21dcf6dc…` |

### 三条注意事项

1. **`predict` 之后不要动 `blind_key.csv`**（哪怕只是打开另存）。一旦字节变了，`verify` 会立刻报不一致——那正是这一步存在的意义，但也别自己制造假警报。
2. **预测分布恰好每类 5 段，不要回避。** 有人会问"怎么这么巧"。答案是：测试集本身就是每类留 5 段（`split_train_test(n_test_per_class=5)`），均衡是设计出来的，不是结果凑出来的。这句话主动说，比被问出来好。
3. **`seal` 会覆盖 `results/blind_clips/` 与 `blind_key.csv`。** 因为内容逐字节相同，`git status` 应当**没有任何变化**。录完顺手 `git status` 一下，如果显示这两个文件被修改，说明有东西不对，先别提交。
