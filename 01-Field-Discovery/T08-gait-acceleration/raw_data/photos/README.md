# photos/ —— 这 20 张是「Phyphox 界面截图」，不是现场同框照

> 这个目录名以前写作「现场认证照」，是不准确的，已改。下面把每一张的真实性质和它能证明的范围写清楚。

## 一、这些图到底是什么

20 张全部是 Phyphox 的 **「加速度（不含 g）」** 界面截图，画面内容是 x / y / z 三轴曲线 + 顶部手机状态栏（时间、电量、信号）。

| 组 | 文件 | 张数 | 对应采集文件 |
| --- | --- | --- | --- |
| 静止 | `S1_STATIC_01_shot1~4.jpg` | 4 | `S1_STATIC_01_20261112-1624.csv` |
| 平地慢走 | `S2_WALK_01_shot1~4.jpg` | 4 | `S2_WALK_01_20261112-1628.csv` |
| 快跑 | `S3_RUN_01_shot1~4.jpg` | 4 | `S3_RUN_01_20261112-1640.csv` |
| 上下楼梯 | `S4_STAIR_shot1~8.jpg` | 8 | `S4_STAIR_UP_01_20261112-1631.csv` / `S4_STAIR_DOWN_01_20261112-1632.csv` |

## 二、它们能证明什么、不能证明什么

| | 内容 |
| --- | --- |
| ✅ 能证明 | 数据是用 Phyphox 采的；波形形态与 CSV 一致（静止近零、快跑幅值大、上下楼正负冲击不对称）；状态栏时间与 CSV 文件名的采集时段落在同一段（如 S1 截图 16:22、对应 CSV 16:24 起录） |
| ✅ 能证明 | 采样入口、轴的命名、单位（m/s²）——即「数据形态」这一层 |
| ❌ 不能证明 | **拍摄者本人当时在现场**。画面里没有人，没有任何可识别的地点特征 |
| ❌ 不能证明 | 手机固定在什么位置、在哪个楼梯拍的、谁在走 |

## 三、和大纲要求的差距（必须如实标出）

《选拔考核大纲》第一阶段总则写的是：

> 须包含本校实地采样原始数据表（`raw_data/`）与**本人现场同框照片**

本目录**不满足**这一条——它是界面截图，不是同框照。之前版本把目录标为「现场认证照」，属于标注错误，已在这个文件里更正。缺口与补救方式记在仓库根目录 `README.md` 的「已知缺口与补救状态」一节。

## 四、补拍清单（5 分钟能完成）

需要补的不是"再截几张图"，而是**人在画面里 + 地点可识别**。建议补 5 张：

1. **静止**：手机置于测量位置，本人与手机、场地同框（能看出是教学楼/宿舍走廊）
2. **慢走**：走道起点，手机在裤兜/手持位置可见，拍一张起步前
3. **快跑**：同上，拍一张起跑前
4. **楼梯**：站在楼梯平台上，手机与楼梯层数标识同框
5. **收尾**：Phyphox 界面 + 手机 + 场地同框（这张同时满足"界面证据"和"现场证据"）

拍摄要求：开定位与时间水印（相机设置里可开），保证照片自带 EXIF 拍摄时间；不要二次截图、不要压缩转发（微信传输会剥离 EXIF）。

## 五、为什么不把这些图删掉

删掉会让"数据是 Phyphox 采的"失去最直接的一条旁证。它们证明不了"本人在场"，但能证明"数据形态与宣称一致"，这两件事不是一回事，都有用。

留着 + 标清楚性质，比留着 + 挂着"现场认证照"的名字要好——后者在被追问时会同时损失可信度和诚实度两项。
